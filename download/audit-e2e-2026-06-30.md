## ❌ Ce qui reste à corriger (1 échec critique + 1 mineur)

### ❌ ÉCHEC CRITIQUE : LinkedIn OAuth — "Client ID introuvable"

**Symptôme :**
```
GET /api/linkedin/auth (avec session valide)
→ HTTP 307
→ Location: /?linkedin=error&message=Client+ID+introuvable.+Réessayez+la+connexion.
```

**Cause racine :**
Le flow LinkedIn OAuth de HERMÈS est **user-configured** (pas env-var-based) :
1. L'utilisateur doit aller dans l'onglet **LinkedIn → Connexion**
2. Saisir son **Client ID** LinkedIn (obtenu depuis le LinkedIn Developer Portal)
3. Saisir son **Client Secret** (optionnel mais recommandé)
4. Cliquer "Connecter LinkedIn"

Le frontend POST ces credentials vers `/api/linkedin/auth` qui les stocke en cookies httpOnly, puis redirige vers LinkedIn.

**Pourquoi le test échoue :** Mon test curl n'envoie pas de `client_id` (ni dans l'URL, ni en cookie), donc le serveur redirige vers l'erreur. Ce n'est PAS un bug — c'est le comportement attendu.

**Action utilisateur requise :**
1. Obtenir un Client ID LinkedIn sur https://www.linkedin.com/developers/apps (créer une app)
2. Configurer dans l'app LinkedIn :
   - **Authorized redirect URL** : `https://linkedin-visual-studio.onrender.com/api/linkedin/callback`
   - **Scopes** : `openid`, `profile`, `email`, `w_member_social`
3. Dans HERMÈS → onglet LinkedIn → Connexion → saisir le Client ID + Secret
4. Cliquer "Connecter LinkedIn"

### ⚠️ Mineur : Redirect URI warning
Le test a détecté que `redirect_uri` n'apparaît pas dans l'URL LinkedIn car le serveur a redirigé vers l'erreur avant de construire l'URL LinkedIn. Ce n'est pas un bug.

## 🔍 Audit code — problèmes potentiels

### 1. ⚠️ `linkedInConfig` stocké en localStorage (non chiffré)
- `src/store/appStore.ts` utilise `persist` avec `name: "hermes-app-store"`
- `linkedInConfig.clientSecret` est stocké en clair dans le localStorage du navigateur
- **Recommandation :** ne stocker que le `clientId` (public), jamais le `clientSecret` côté client. Le secret devrait être saisi à chaque session ou stocké côté serveur chiffré en DB.

### 2. ⚠️ `clientSecret` envoyé via cookie httpOnly (10 min TTL)
- `src/app/api/linkedin/auth/route.ts` ligne 64 : cookie `li_client_secret` avec `Max-Age=600`
- C'est acceptable pour le flow OAuth court terme, mais le secret transite par le POST body
- **Recommandation :** s'assurer que le POST est bien en HTTPS (Render l'impose déjà)

### 3. ⚠️ Pas de validation du `state` CSRF sur le callback LinkedIn
- À vérifier dans `src/app/api/linkedin/callback/route.ts` (non audité en détail)
- **Recommandation :** valider que le `state` reçu correspond au cookie `li_oauth_state`

### 4. ⚠️ Demo password hardcoded dans le code
- `DEMO_INITIAL_PASSWORD = "Demo-Hermes-2024"` dans `auth-config.ts`
- Acceptable pour un compte démo, mais devrait être supprimé en production réelle

### 5. ✅ Pas de leak du GitHub token dans le code
- Vérifié : le token GitHub est uniquement dans l'URL du remote git (non commité)
